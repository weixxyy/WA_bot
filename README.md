# WA_bot — бот WhatsApp Web

Бот на Playwright (Firefox), который заходит по invite-ссылкам в группы WhatsApp
и отправляет в них сообщение. Ссылки лежат в `urls.txt` (по одной в строке),
текст сообщения — в `send_to.txt`.

Есть и второй сценарий — `join_groups.py`: он только вступает по тем же ссылкам
(сообщений не отправляет) и раскладывает группы по типам в отдельные файлы
`only_admins_groups.txt` / `closed_groups.txt` / `open_groups.txt`. Пометка
«нужен запрос на вступление» неизменна: ссылка из `closed_groups.txt` больше не
переезжает в другие списки. Ставит её `join_groups.py`, а также `script.py` —
когда сам нажимает «Запрос на вступление». Если заявку подали в прошлом прогоне и
её ещё не одобрили, WhatsApp показывает на кнопке «Отменить запрос»: бот её не
нажимает (отмена сбросила бы заявку), пишет в лог «заявка на вступление уже
подана», закрепляет ту же пометку и идёт к следующей ссылке. Если же `script.py`
просто не удалось отправить сообщение в уже помеченную группу, в лог идёт
«профиль ещё не одобрили», и обход переходит к следующей ссылке.

## Требования

- Python 3.10+ (проверено на 3.14)
- Playwright 1.63 и скачанный браузер Firefox
- Linux / macOS / Windows

iOS (iPhone / iPad) для запуска не подходит: Playwright управляет настоящим
Firefox отдельным процессом, а на iOS такого браузера нет. Как быть — в разделе
«macOS и iOS».

## Быстрый старт

Linux / macOS:

```bash
./setup.sh
./run.sh                # по расписанию: 09:00 и 18:00, пока не остановишь Ctrl+C
./run.sh --once         # один прогон и выход
```

Windows:

```bat
setup.bat
run.bat                 # по расписанию: 09:00 и 18:00, пока не остановишь Ctrl+C
run.bat --once          # один прогон и выход
```

macOS: то же самое можно делать двойным кликом из Finder — `setup.command`,
`login.command`, `run.command`, `join.command` (подробности — в разделе
«macOS и iOS»). Остановить запущенное можно и из самой панели — кнопкой
«Остановить панель», — и командой `./stop.sh` или двойным кликом по
`stop.command` (если браузера под рукой нет или вкладка уже закрыта):
см. «Остановка панели и прогонов».

То же самое вручную: `.venv/bin/python main.py` (Windows:
`.venv\Scripts\python.exe main.py`). Подробности — в разделе
«Расписание запусков» ниже.

Добавить новый аккаунт или удалить существующий профиль (интерактивно) —
`./login.sh` на Linux / macOS и `login.bat` на Windows. Всё то же самое (плюс
правка сообщения, ссылок и расписания) доступно и из локальной веб-панели —
`./web.sh` (Windows: `web.bat`); подробности — в разделе «Веб-панель».

Отдельный сценарий `join_groups.py` (обёртки — `./join.sh`, `join.bat`,
`join.command`) вступает по тем же ссылкам в группы, ничего не отправляя, и
раскладывает их по типам в три файла — подробности в разделе «Вступление в
группы».

Скрипт установки создаёт `.venv`, при необходимости доставляет в окружение pip,
ставит зависимости, скачивает Firefox для Playwright и создаёт пустой каталог
`profiles/`.

Ссылки-приглашения кладутся в `urls.txt`, текст отправляемого сообщения — в
`send_to.txt`. Оба файла лежат рядом с кодом (шаблоны — `urls.txt.example` и
`send_to.txt.example`) и перечитываются перед каждым прогоном, поэтому правки
подхватываются без перезапуска бота.

## Расписание запусков (`run.sh` / `run.command` / `run.bat`)

Бот не висит в памяти постоянно, а просыпается в заданные времена суток —
`scheduler.DEFAULT_RUN_AT` (по умолчанию 09:00 и 18:00, **местное время
машины**). Времена можно переопределить из командной строки:

```bash
./run.sh --at 10:30 22:15        # Windows: run.bat --at 10:30 22:15
```

Что важно знать:

- ближайшее время считается **заново после каждого прогона**. Если прогон занял
  больше времени, чем пауза до следующего слота, слот пропускается и не
  «догоняется»;
- ошибка внутри прогона (Playwright, сеть, проблемный профиль) не останавливает
  планировщик: она попадает в лог (`logs/wa_bot.log`), а следующий запуск всё
  равно планируется;
- остановить бота можно `Ctrl+C` — это штатное завершение, без стек-трейса;
- время указывается в формате `ЧЧ:ММ`, дубликаты схлопываются, а опечатка в
  `--at` приводит к понятной ошибке сразу, ещё до первого прогона;
- `--once` выполняет один прогон и выходит — удобно для отладки и для запуска
  извне (например, из системного `cron` или `systemd` timer).

То же самое вручную (без обёрток `run.sh` / `run.bat`):

```bash
.venv/bin/python main.py                       # по расписанию
.venv/bin/python main.py --once                # один прогон
.venv/bin/python main.py --at 09:00 18:00      # свои времена
.venv/bin/python main.py --help
```

## Вступление в группы (`join.sh` / `join.command` / `join.bat`)

Отдельный сценарий для тех же `urls.txt` и `profiles/`: он **только** вступает в
группы по ссылкам (кнопка «Вступить в группу» или «Запрос на вступление», а если
заявка уже подана — «Отменить запрос») и ничего не отправляет. Заодно он
раскладывает группы по типам в три файла рядом с кодом:

| Файл | Что это за группа |
| --- | --- |
| `only_admins_groups.txt` | писать могут только админы (в `script.py` такие группы пропускаются, сообщение в них не уходит) |
| `closed_groups.txt` | вступление требует одобрения: на кнопке «Запрос на вступление», а после отправки заявки — «Отменить запрос» |
| `open_groups.txt` | все остальные |

Группы, из которых профиль выгнан, и ссылки, на которых сценарий упал, в списки
не попадают: тип такой группы определит другой профиль, а мусор в файлах не
нужен. Ссылки дописываются без дублей, так что повторный прогон ничего не
размножает. Файлы читаются панелью (вкладка «Ссылки») и в git не попадают.

```bash
./join.sh                                       # по расписанию: 10:00 и 19:00
./join.sh --once                                # один прогон и выход
./join.sh --at 10:00 19:00                      # свои времена
./join.sh --help
```

Вручную (без обёртки `join.sh`):

```bash
.venv/bin/python join_groups.py                 # по расписанию
.venv/bin/python join_groups.py --once          # один прогон и выход
.venv/bin/python join_groups.py --at 10:00 19:00   # свои времена
.venv/bin/python join_groups.py --help
```

Windows: `join.bat` вместо `./join.sh`, macOS: двойной клик по `join.command`
или `./join.command` из терминала.

Что важно знать:

- расписание по умолчанию — `scheduler.DEFAULT_JOIN_RUN_AT` (10:00 и 19:00,
  местное время); оно независимо от расписания рассылки (`DEFAULT_RUN_AT`),
  а в веб-панели у него своё поле;
- сценарий держит ту же блокировку `logs/wa_bot.lock`, что и `main.py`: пока
  работает рассылка или панель, второй прогон без `--force` не стартует (и
  наоборот), потому что два прогона по одним профилям ломают Firefox-профиль;
- статистику рассылки (`bot_stats.json`, `logs/stats_summary.json`) скрипт не
  трогает, чтобы не затирать данные `main.py`.

## Веб-панель (`web.sh` / `web.command` / `web.bat`)

Тот же бот, но с локальным интерфейсом в браузере: текст сообщения, список
ссылок, расписание и номера правятся мышкой, без ручного редактирования файлов.
Панель — **надстройка**: `main.py`, `script.py`, `login.py` и остальные сценарии
остаются как есть, панель лишь вызывает их функции.

```bash
./web.sh                 # Windows: web.bat; macOS: двойной клик по web.command
```

Панель поднимается на `http://127.0.0.1:8765` и открывается в браузере
автоматически. Пока она работает, она держит ту же блокировку, что и `run.sh`:
второй экземпляр (`main.py`, `run.sh`, `join.sh`, `login.sh`) не стартует — и
наоборот.

Что можно делать из панели:

- **Сообщение** — редактировать `send_to.txt`;
- **Ссылки** — редактировать `urls.txt`, вставить любой текст и выловить из него
  все ссылки вида `chat.whatsapp.com/...`, а ниже — три готовых списка
  (`only_admins_groups.txt`, `closed_groups.txt`, `open_groups.txt`), которые
  заполняет скрипт вступления (только для чтения);
- **Расписание** — включать/выключать автозапуск и задавать времена (хранится в
  `settings.json`, шаблон — `settings.json.example`); под расписанием рассылки —
  отдельное расписание скрипта вступления (`join_enabled` / `join_times`);
- **Номера** — смотреть профили из `profiles/`, проверять статус входа, добавлять
  новый номер (откроется видимый Firefox — нужно отсканировать QR-код) и удалять
  профили;
- **Журнал** — последние прогоны из `logs/stats_summary.json` и хвост
  `logs/wa_bot.log`. В шапке панели три кнопки: «Запустить сейчас» (рассылка),
  «Запустить вступление» (`join_groups.py`) и «Остановить панель» — она гасит
  панель вместе с планировщиком и снимает блокировку бота, то есть делает то же,
  что `Ctrl+C` в окне панели или `./stop.sh` (подробности — в разделе «Остановка
  панели и прогонов»).

Аргументы:

```bash
./web.sh --port 9000      # другой порт
./web.sh --no-browser     # не открывать браузер автоматически
```

Что важно знать:

- правки **данных** подхватываются **без перезапуска**: и панель, и бот
  перечитывают `urls.txt` / `send_to.txt` перед каждым прогоном, а `settings.json`
  — на каждом цикле планировщика панели. Правки **кода** (`*.py`,
  `panel/app.js`, `panel/index.html`) — наоборот, только после перезапуска панели:
  Python читает модули один раз, и файл на диске оказывается новее кода в памяти
  процесса. Пока правки не применены, в шапке панели висит чип «код новее —
  перезапустите панель». Перезапуск: остановите панель (`Ctrl+C` в её окне или
  `./stop.sh`, если окна нет) и снова запустите `./web.sh`; при живой панели
  `./web.sh` её не перезапускает — просто открывает уже открытую и выходит;
- страницу в браузере обновляйте с `Ctrl+Shift+R`: старый `app.js` умеет молча
  ничего не делать (кнопка в HTML уже есть, а обработчика в нём ещё нет). Если
  страница устарела, панель сама скажет об этом чипом «страница устарела»;
- панель слушает только `127.0.0.1` и проверяет заголовок `Host`, поэтому доступна
  лишь с того же компьютера. Изменяющие запросы дополнительно требуют CSRF-токен,
  который выдаётся вместе со страницей;
- в шапке панели есть кнопка **«Остановить панель»**: она выключает панель (а это
  и есть процесс бота) — с подтверждением в браузере, даже когда окна терминала
  рядом нет (`nohup ./web.sh &`, запуск из IDE). Если в этот момент идёт прогон,
  панель сначала дожидается его завершения — до 15 секунд, и лишь потом
  выключается; на экране видно, как идёт ожидание. Кнопка заменяет `./stop.sh`
  для обычного случая, а сам скрипт остаётся на случай, когда браузер недоступен;
- закрытие окна терминала (`SIGHUP`) и `Ctrl+C` останавливают панель штатно и
  освобождают блокировку. Если окна у панели нет (`nohup ./web.sh &`, запуск из
  IDE или из другого сеанса), а браузер недоступен, выручает скрипт `./stop.sh`
  (Windows: `stop.bat`, macOS: `stop.command`) — подробности в разделе «Остановка
  панели и прогонов». При живой панели `./web.sh` больше не исчезает молча: панель
  скажет «Бот уже работает», окно дождётся Enter и подскажет ту же команду;
- добавление номера требует **видимого** браузера: панель откроет Firefox на
  `web.whatsapp.com`, дождитесь сканирования QR-кода телефоном (до 5 минут);
- картинки и нестандартные паузы панель не настраивает — это по-прежнему требует
  правки `script.py`.

Дополнительные зависимости панели (`fastapi`, `uvicorn`) уже в
`requirements.txt`; при обновлении проекта не забудьте
`python -m pip install -r requirements.txt`.

## Остановка панели и прогонов (`stop.sh` / `stop.command` / `stop.bat`)

Самый простой способ выключить панель — кнопка **«Остановить панель»** в её
интерфейсе: она гасит тот же процесс, что и `Ctrl+C`, и не требует ни окна
терминала, ни скриптов. `stop.sh` нужен, когда браузера под рукой нет или
вкладка уже закрыта (например, панель запущена через `nohup ./web.sh &` или из
IDE, а выключить её надо из терминала).

Рассылка и вступление в группы штатно завершаются по `Ctrl+C` в своём окне, и
панель тоже. Но панель умеет работать и без окна — из другого сеанса, из IDE или
через `nohup ./web.sh &`: тогда `Ctrl+C` нажать негде, а процесс продолжает
держать блокировку `logs/wa_bot.lock`, и ни `run.sh`, ни `join.sh`, ни второй
`./web.sh` не стартуют. Скрипт остановки находит такой процесс по служебным
файлам и гасит его:

```bash
./stop.sh                # Windows: stop.bat; macOS: двойной клик по stop.command
```

Кого останавливать, `stop.py` определяет сам:

- сначала смотрит `logs/wa_panel.json` — там PID и порт работающей панели;
- затем `logs/wa_bot.lock` — так же останавливается прогон (`main.py`,
  `join_groups.py`), запущенный без своего окна.

Содержимое lock-файла живёт и после завершения процесса, поэтому «живость» PID
проверяется отдельно, а перед отправкой сигнала сверяется командная строка
процесса. Если номер PID успел достаться чужой программе, скрипт ничего не
трогает и сообщает об этом (код возврата 1).

Аргументы:

```bash
./stop.sh --dry-run      # только показать, что будет остановлено
./stop.sh --force        # не просить завершиться, а убивать сразу (SIGKILL, taskkill /F)
./stop.sh --help
```

Как это работает:

- Linux / macOS: процессу уходит `SIGTERM` — панель останавливает планировщик,
  освобождает блокировку и убирает `logs/wa_panel.json`. Скрипт ждёт завершения
  до 10 секунд и лишь потом советует `--force`;
- кнопка «Остановить панель» делает то же самое, но без сигнала: процесс гасит
  сам себя изнутри, поэтому `logs/wa_panel.json` и блокировка убираются всегда —
  подчищать их скриптом, как после `SIGTERM`, не нужно. Если идёт прогон, панель
  ждёт его завершения (до 15 секунд) и только потом выключается;
- Windows: `taskkill /PID <номер> /T`, с `--force` — `/F`;
- если ничего не запущено, скрипт так и говорит и выходит с кодом 0: повторный
  запуск `./stop.sh` безопасен;
- заодно подчищается протухший `logs/wa_panel.json`: панель, закрытая сигналом,
  не всегда успевает удалить его сама.

Если `./web.sh` запущен при живой панели, окно больше не закрывается молча:
панель скажет «Бот уже работает», скрипт дождётся Enter и подскажет `./stop.sh`.
Так же ведут себя `web.bat` и `web.command`.

## Установка вручную

```bash
python -m venv .venv                  # 1. окружение
source .venv/bin/activate             #    Windows: .venv\Scripts\activate
python -m pip --version               #    если "No module named pip" — см. ниже
python -m pip install -r requirements.txt   # 2. зависимости
python -m playwright install firefox  # 3. браузер (без него бот не запустится)
# Linux, если не хватает системных библиотек:
# python -m playwright install-deps firefox
mkdir -p profiles                     # 4. каталог профилей (создаётся и самим ботом)
python main.py                        # 5. запуск
```

Если `python -m pip --version` отвечает `No module named pip`, значит в сборке
Python нет модуля `ensurepip` (в Debian/Ubuntu он лежит в пакете `python3-venv`,
и `python -m venv` при его отсутствии молча создаёт окружение без pip).
`./setup.sh` (Windows: `setup.bat`) сам доставляет pip в `.venv` через
[`get-pip.py`](https://bootstrap.pypa.io/get-pip.py); вручную это выглядит так:

```bash
curl -fsSL https://bootstrap.pypa.io/get-pip.py -o /tmp/get-pip.py
python /tmp/get-pip.py                # python — уже из .venv
# либо, если нужен и системный pip: sudo apt install python3.14-venv
```

В PyCharm: выберите интерпретатор `.venv` — зависимости из `requirements.txt`
подтянутся при синхронизации окружения, шаг с `playwright install firefox`
нужно выполнить из терминала один раз.

## macOS и iOS

### macOS: двойной клик в Finder

`setup.command`, `login.command`, `run.command`, `join.command`, `stop.command` —
те же действия, что и `.sh`-скрипты, но их можно запускать двойным кликом из
Finder (macOS открывает `.command` в Terminal). Это тонкие обёртки над `setup.sh` /
`login.sh` / `run.sh` / `join.sh` / `stop.sh`: вся логика остаётся в `.sh`,
поэтому из терминала пользуйтесь привычными `./setup.sh`, `./login.sh`,
`./run.sh`, `./join.sh`, а `.command` оставьте для Finder. Аргументы
пробрасываются, так что `./run.command --once`, `./join.command --at 10:30`,
`./login.command --delete 7` и `./stop.command --force` работают так же, как их
`.sh`-версии.

`stop.command` особенно полезен, когда панель запущена без своего окна Terminal:
двойной клик — и процесс остановлен (подробности в разделе «Остановка панели и
прогонов»).

Что делают обёртки:

- дописывают в `PATH` каталоги `/opt/homebrew/bin` (Apple Silicon) и
  `/usr/local/bin` (Intel): Finder запускает Terminal с «чистым» окружением, в
  котором `python3` из Homebrew не виден;
- ждут Enter перед закрытием окна — иначе Terminal закроется сразу после выхода
  и ошибку прочитать не получится (`WA_BOT_NO_PAUSE=1` отключает паузу, если
  обёртку зовут из другого скрипта).

Если macOS отказывается открывать файл («не удалось проверить разработчика» или
«нет прав на выполнение»), снимите карантин и верните право на запуск:

```bash
xattr -d com.apple.quarantine setup.command login.command run.command join.command stop.command
chmod +x setup.command login.command run.command join.command stop.command
```

Особенности macOS, о которых стоит знать:

- `python3` в macOS — это Python 3.9 из Xcode Command Line Tools, а проекту нужен
  3.10+. Поставьте свежий (`brew install python@3.13`) и запустите установку с
  ним: `PYTHON_BIN=python3.13 ./setup.sh`. `setup.sh` проверяет версию сам и
  подскажет то же самое, если она слишком старая;
- `playwright install-deps` — шаг только для Linux: в macOS нужные библиотеки уже
  в системе, поэтому `setup.sh` пропускает его сам, даже если задан
  `INSTALL_DEPS=1`;
- чтобы прогоны по расписанию не пропускались, Mac не должен спать: либо
  отключите сон в «Системных настройках → Энергосбережение», либо запускайте бота
  через `caffeinate -i ./run.sh`.

### iOS (iPhone / iPad)

Запустить бота на iPhone или iPad нельзя: Playwright управляет настоящим
браузером Firefox, который работает отдельным процессом, а на iOS сторонние
браузерные движки запрещены (только WebKit) и Python-скрипты из терминала тоже
не запускаются — `.sh`, `.command` и `.bat` там просто нечему выполнять. Поэтому
бот живёт на Mac или на сервере с Linux, а iPhone используется как пульт и как
сканер QR-кода:

- QR при добавлении аккаунта сканируется телефоном: в WhatsApp откройте
  «Связанные устройства» → «Связать устройство» и наведите камеру на QR-код,
  который открыл `./login.sh` (или `./login.command`) на Mac;
- управлять ботом с iPhone удобно по SSH: поставьте клиент (Termius, Blink,
  Secure ShellFish), подключитесь к Mac и запускайте там `./run.sh`,
  `./run.command --once`, `./login.sh --list`, а логи смотрите той же командой
  `tail -f logs/wa_bot.log`;
- если держать SSH-соединение не хочется, запустите `./run.command` на Mac
  двойным кликом и оставьте окно Terminal открытым, а с телефона поглядывайте в
  `logs/wa_bot.log` (например, через приложение «Файлы», если проект лежит в
  iCloud Drive).

## Каталог `profiles/`

Внутри `profiles/` лежит по одному каталогу Firefox-профиля на каждый аккаунт
WhatsApp (например `profiles/whatsapp_profile1` или `profiles/7` — имя профиля
задаётся при его добавлении). В профиле хранится сессия
WhatsApp Web (`cookies.sqlite`, `key4.db`, `storage`), то есть фактический доступ
к аккаунту, поэтому:

- содержимое `profiles/` **никогда не коммитится** (см. `.gitignore`);
- в git попадает только заглушка `profiles/.gitkeep`, чтобы папка появлялась
  сразу после клонирования проекта;
- каталог создаётся автоматически (`login_check.ensure_profiles_dir()`) при
  первом запуске — даже если `profiles/` отсутствует или пуст.

Чтобы добавить аккаунт, положите в `profiles/` каталог с уже выполненным входом
в WhatsApp Web (Firefox) — либо добавьте его интерактивно, см. раздел
«Управление аккаунтами» ниже. Там же профиль можно удалить (вручную это то же
самое — просто удалить его каталог).

## Управление аккаунтами (`login.sh` / `login.command` / `login.bat`)

`login.py` умеет и добавлять аккаунты, и удалять профили. С аргументами он
браузер не открывает: можно просто посмотреть список профилей или удалить
нужные.

Linux / macOS:

```bash
./login.sh                          # интерактивное меню
./login.sh --list                   # показать профили из profiles/
./login.sh --delete 7               # удалить профиль profiles/7 (с подтверждением)
./login.sh --delete 7 8 --yes       # удалить без подтверждения
./login.command                     # macOS: то же, но двойным кликом в Finder
```

Windows:

```bat
login.bat
login.bat --list
login.bat --delete 7
login.bat --delete 7 8 --yes
```

То же самое вручную:

```bash
.venv/bin/python login.py           # Windows: .venv\Scripts\python.exe login.py
```

### Добавление аккаунтов

Скрипт спрашивает, сколько аккаунтов добавить, и как назвать каждый профиль
(введённый номер становится именем каталога в `profiles/`). После этого по
очереди открывается окно Firefox на web.whatsapp.com — нужно отсканировать
QR-код телефоном и нажать Enter в консоли. Браузер открывается видимым
(не headless), иначе QR-код не отсканировать.

```
Управление аккаунтами WhatsApp
  1 — добавить аккаунты
  2 — удалить профиль
  0 — выйти
Действие [1]:
Сколько аккаунтов хотите добавить? 2
Название (номер) профиля №1: 7
Название (номер) профиля №2: 8
```

Enter в меню — это пункт 1, то есть добавление: без аргументов скрипт ведёт
себя так же, как раньше. В результате появятся каталоги `profiles/7` и
`profiles/8`. Существующие профили скрипт не трогает: если каталог с таким
номером уже есть, он попросит ввести другой номер.

### Удаление профиля

Удаление необратимо: вместе с каталогом профиля пропадают сессия WhatsApp
(`cookies.sqlite`, `key4.db`, `storage`) и файл `bot_stats.json` — аккаунт
придётся добавлять заново. Поэтому скрипт сначала показывает полные пути и
спрашивает подтверждение (`[y/N]`, по умолчанию — нет).

```
Действие [1]: 2
Доступные профили:
  1) whatsapp_profile1
Номера или названия профилей (Enter — отмена): 1

Будут удалены:
  /home/user/WA_bot/profiles/whatsapp_profile1
Вместе с профилем удалится сессия WhatsApp и файл bot_stats.json — аккаунт придётся добавлять заново.
Продолжить? [y/N]: y
Профиль /home/user/WA_bot/profiles/whatsapp_profile1 удалён.
```

Что стоит знать:

- профиль указывается номером из списка или именем каталога: `1`, `7`, `7, 8`;
- если бот сейчас работает, удаление отклоняется — сначала остановите его
  (Ctrl+C). Обойти проверку можно только осознанно, флагом `--force`;
- удаляются только каталоги внутри `profiles/`: пути вида `../что-то` и
  служебные файлы (`.gitkeep`) отклоняются;
- каталог профиля можно удалить и вручную — результат тот же.

## Статистика профиля: `bot_stats.json`

В каждом каталоге профиля бот ведёт файл `bot_stats.json` (например
`profiles/whatsapp_profile1/bot_stats.json`). Он создаётся автоматически
перед обходом ссылок и содержит:

- `kicked_count` — сколько групп, из которых аккаунт был выгнан, встретилось
  за текущий прогон (в начале работы с профилем счётчик обнуляется);
- `last_date_change` — время последней записи в файл (ISO-формат,
  например `2026-09-25T16:12:33`).

Файл лежит внутри `profiles/`, поэтому в git он не попадает.

Сразу после отработки каждого профиля бот выводит в лог его итог — сколько
групп этот аккаунт «потерял» за прогон, например:

```
Итог по профилю profiles/whatsapp_profile1: выгнан из 2 групп(ы) за прогон
```

Строка печатается и когда сценарий прервался ошибкой: `bot_stats.json`
к этому моменту уже записан.

### Сводка по прогонам: `logs/stats_summary.json`

После обхода всех профилей бот дописывает сводку прошедшего прогона в
`logs/stats_summary.json` — историю последних `MAX_RUNS_IN_SUMMARY`
(по умолчанию 100) прогонов:

```json
[
  {
    "date": "2026-09-29T15:10:00",
    "total_kicked": 3,
    "profiles": {
      "whatsapp_profile1": 2,
      "whatsapp_profile2": 1
    }
  }
]
```

- `date` — время окончания прогона (ISO-формат);
- `total_kicked` — сумма по профилям, чью статистику удалось прочитать;
- `profiles` — `{имя каталога профиля: сколько групп, откуда выгнали}`;
  если файл профиля прочитать не удалось, вместо числа будет `null`.

Файл лежит в `logs/`, поэтому в git он тоже не попадает.

## Как это работает

1. `main.py` — точка входа: настраивает логи, разбирает аргументы (`--once`,
   `--at`, `--force`) и либо делает один прогон (`run_once()`), либо отдаёт его
   планировщику. Пока бот работает, он держит блокировку `logs/wa_bot.lock`
   (`bot_lock.py`), поэтому второй экземпляр без `--force` не стартует: два
   прогона по одним профилям ломают Firefox-профиль. Прогон: создаёт
   `profiles/`, запускает Playwright, проверяет профили и обходит группы;
   ошибка на одном профиле не прерывает остальные.
2. `scheduler.py` — расписание: считает ближайшее время из
   `DEFAULT_RUN_AT`, спит до него и вызывает прогон; упавший прогон не
   останавливает цикл (см. «Расписание запусков»).
3. `login.py` (`login.sh` / `login.bat`) — управление аккаунтами: интерактивное
   меню из двух действий (добавить аккаунты и удалить профиль) плюс разовые
   команды `--list` / `--delete` (см. «Управление аккаунтами»).
4. `login_check.py` — проверяет каждый профиль из `profiles/`
   (`check_profile()` открывает web.whatsapp.com) и делит их на `logged` /
   `unlogged`; если страница не открылась (сеть, DNS, прокси), профиль
   пропускается с ошибкой в логе, а остальные проверяются дальше.
5. `script.py` — для каждого залогиненного профиля создаёт/обнуляет
   `bot_stats.json`, проходит по ссылкам из `urls.txt`, вступает в группу
   и отправляет текст из `send_to.txt`; если аккаунт из группы выгнали,
   увеличивает `kicked_count`. Ошибка на одной ссылке (не нашлась кнопка
   входа, таймаут загрузки, падение вкладки, сеть) не прерывает обход
   остальных: ссылка с traceback попадает в лог и пропускается, дальше
   обрабатывается следующая группа. Если вместо «Вступить в группу» на кнопке
   написано «Запрос на вступление», бот нажимает её, закрепляет ссылку в
   `closed_groups.txt` (`group_lists.move_to_closed()`), ждёт 5 секунд и
   переходит к следующей ссылке (сообщение в такую группу не отправляется — бота
   в ней ещё нет); при следующих прогонах ссылка уже помечена, и бот просто
   пропускает группу. Если заявку подали раньше и её ещё не одобрили, на кнопке
   написано «Отменить запрос»: бот её не нажимает (отмена сбросила бы заявку),
   пишет в лог «заявка на вступление уже подана», закрепляет ссылку в
   `closed_groups.txt` и переходит к следующей. После последней ссылки бот
   дополнительно ждёт 5 секунд,
   прежде чем закрыть окно. Если вместо поля ввода WhatsApp показывает, что
   писать в группу могут только админы, группа пропускается — такие группы
   собирает `join_groups.py`. Если сообщение отправить не удалось (кнопка
   «Запрос на вступление» всё ещё на месте, поля ввода нет или отправка упала),
   а ссылка помечена как «нужен запрос» в `closed_groups.txt`, в лог идёт
   «Профиль ... ещё не одобрили в группе ... — пропускаем группу», и обход
   переходит к следующей ссылке (`script._skip_not_approved()`). Ссылки и текст
   читает `urls_list.py` (`load_invite_urls()` / `load_message()`) — заново перед
   каждым прогоном.
   После отработки профиля `main.py` печатает его итог
   (`script.log_stats()`), а в конце прогона дописывает сводку по всем
   профилям в `logs/stats_summary.json` (`script.save_run_summary()`).
6. `join_groups.py` — второй сценарий по тем же ссылкам: вступает в группы
   (кнопка «Вступить в группу» или «Запрос на вступление»; при уже поданной
   заявке — «Отменить запрос», её бот не нажимает, а помечает ссылку) и ничего
   не отправляет. Заодно раскладывает группы по файлам `only_admins_groups.txt` /
   `closed_groups.txt` / `open_groups.txt` (запись — `group_lists.py`): «только
   админы», «нужен запрос» и все остальные. Выгнанные группы и упавшие ссылки в
   списки не попадают. Пометка «нужен запрос» неизменна: ссылка, попавшая в
   `closed_groups.txt`, больше не переезжает в другие списки, а если оказалась в
   них раньше — при прогоне убирается оттуда (`group_lists.move_to_closed()`);
   снять пометку можно только вручную, удалив строку из файла. Своё расписание по
   умолчанию — `DEFAULT_JOIN_RUN_AT` (10:00 и 19:00), статистику рассылки скрипт
   не трогает.
7. `logger.py` — логи в консоль и в `logs/wa_bot.log` с ротацией.
8. `bot_lock.py` — блокировка `logs/wa_bot.lock`: не даёт запустить второй
   экземпляр бота (`main.py`, `join_groups.py`) и удалить профиль во время
   прогона (`login.py`).

## Настройка

- Ссылки-приглашения: `urls.txt` — по одной ссылке в строке; пустые строки и
  строки, начинающиеся с `#`, игнорируются, пробелы по краям обрезаются,
  дубликаты схлопываются с сохранением порядка. Шаблон — `urls.txt.example`,
  пути задаются константами `URLS_FILE` / `MESSAGE_FILE` в `urls_list.py`.
- Текст сообщения: `send_to.txt` берётся целиком, переносы строк сохраняются
  (многострочный текст уходит одним сообщением). Если файла нет или он пуст,
  отправляется `urls_list.DEFAULT_MESSAGE` (`ping`) с предупреждением в логе.
- Времена автозапуска рассылки: `scheduler.DEFAULT_RUN_AT` либо аргумент `--at`
  (см. «Расписание запусков»); времена вступления — `scheduler.DEFAULT_JOIN_RUN_AT`
  либо `--at` у `join_groups.py`.
- Расписание из веб-панели: `settings.json` — `enabled` / `times` (рассылка) и
  `join_enabled` / `join_times` (вступление), шаблон — `settings.json.example`.
- Файлы с типами групп: `ONLY_ADMINS_FILE`, `CLOSED_FILE`, `OPEN_FILE` в
  `group_lists.py` (по умолчанию `only_admins_groups.txt`, `closed_groups.txt`,
  `open_groups.txt` рядом с кодом). Пометка «нужен запрос» неизменна: закрепить
  её и убрать ссылку из других списков можно через
  `group_lists.move_to_closed()`, проверить — через `group_lists.is_closed()`.
- Уровень и файл логов: `logger.setup_logging(level=..., log_file=...)`.
- Каталог профилей: константа `PROFILES_DIR` в `login_check.py`
  (по умолчанию `<каталог проекта>/profiles`).
- Файл блокировки запуска: `LOCK_FILE` в `bot_lock.py`
  (по умолчанию `<каталог проекта>/logs/wa_bot.lock`).
- Сводка по прогонам: константы `SUMMARY_FILE` и `MAX_RUNS_IN_SUMMARY` в
  `script.py` (по умолчанию `<каталог проекта>/logs/stats_summary.json`
  и 100 последних прогонов).

## Частые проблемы

- `Файл со ссылками .../urls.txt не найден` — положите `urls.txt` рядом с кодом
  (по одной ссылке в строке) или скопируйте `urls.txt.example`. Пока файла нет,
  прогон не начинается.
- В логе `В .../urls.txt нет ни одной ссылки — прогон пропущен` — файл есть, но в
  нём только пустые строки и комментарии (`#`): добавьте хотя бы одну ссылку.
- В логе `Файл с текстом сообщения .../send_to.txt не найден, отправляю 'ping'` —
  файла с текстом нет или он пуст, бот работает с текстом по умолчанию
  (`urls_list.DEFAULT_MESSAGE`).
- `No module named pip` (при этом `python -m venv` об этом не предупредил) —
  в сборке Python нет модуля `ensurepip`, поэтому окружение создалось без pip.
  `./setup.sh` / `setup.bat` доставляют pip сами (`python -m ensurepip`, а если
  его нет — скачанный `get-pip.py`). Вручную: `sudo apt install python3.14-venv`
  либо `curl -fsSL https://bootstrap.pypa.io/get-pip.py -o /tmp/get-pip.py &&
  .venv/bin/python /tmp/get-pip.py`. Адрес get-pip.py переопределяется:
  `GET_PIP_URL=... ./setup.sh`.
- `Executable doesn't exist at .../firefox-...` — не выполнен
  `python -m playwright install firefox`.
- `Firefox не запускается, не хватает библиотек` (Linux) —
  `python -m playwright install-deps firefox` (нужен sudo).
- В логе `В .../profiles нет ни одного авторизованного профиля` — в `profiles/`
  ещё нет ни одного каталога с выполненным входом в WhatsApp Web.
- В логе `Не удалось открыть WhatsApp Web для профиля ...` и
  `Профиль ... пропущен: не удалось проверить` — страница не загрузилась
  (нет сети, блокировка, прокси). Такой профиль не попадает ни в `logged`,
  ни в `unlogged`, остальные проверяются дальше.
- В логе `Бот уже запущен ...` — второй экземпляр бота не стартует, пока
  работает первый (блокировка `logs/wa_bot.lock`). Остановите работающий бот
  (Ctrl+C) либо запустите с `--force`, если второй прогон действительно нужен.
  Если у процесса нет своего окна (`nohup ./web.sh &`, запуск из IDE или из
  другого сеанса), `Ctrl+C` нажать негде — тогда помогает `./stop.sh` (Windows:
  `stop.bat`): он находит процесс по `logs/wa_panel.json` и `logs/wa_bot.lock`.
  Это же сообщение появится у `join.sh`, если в этот момент идёт рассылка (и
  наоборот): оба сценария работают по одним и тем же профилям Firefox.
- В логе `В .../urls.txt нет ни одной ссылки — прогон пропущен` (скрипт
  вступления) — добавьте ссылки в `urls.txt` (проще всего в панели, вкладка
  «Ссылки») и запустите снова: браузеры на пустом списке не поднимаются.
- В логе `Профиль ... ещё не одобрили в группе ... — пропускаем группу` — это не
  ошибка: ссылка помечена в `closed_groups.txt` как «нужен запрос на
  вступление», а отправить сообщение не удалось, значит заявку ещё не одобрили.
  Пометку ставит `join_groups.py`, а также сама рассылка, когда нажимает «Запрос
  на вступление». Пометка неизменна, поэтому группа и дальше будет пропускаться,
  даже если бота в неё потом одобрят. Если группа снова стала обычной, удалите её
  строку из `closed_groups.txt`.
- В логе `Пометка группы ... неизменна: тип не пересчитываем` — `join_groups.py`
  встретил ссылку, которая уже лежит в `closed_groups.txt`: тип такой группы не
  пересчитывается, в `only_admins_groups.txt` / `open_groups.txt` она не попадёт.
- `Не удалось удалить ... каталог занят` — в этот момент работает бот или
  Firefox держит профиль. Остановите бота (Ctrl+C), закройте Firefox и
  повторите: `./login.sh --delete <имя>`.
- macOS: `.command` не открывается («не удалось проверить разработчика» либо
  «нет прав на выполнение») — файл под карантином или потерял право на запуск
  после распаковки архива:
  `xattr -d com.apple.quarantine *.command && chmod +x *.command`.
- macOS: `Нужен Python 3.10 или новее` — системный `python3` из Xcode Command
  Line Tools это 3.9. Поставьте `brew install python@3.13` и запустите установку
  с ним: `PYTHON_BIN=python3.13 ./setup.sh`.
- Прогоны по расписанию пропускаются, когда компьютер спит (заметнее всего на
  ноутбуках). На macOS помогает `caffeinate -i ./run.sh`, на Windows — отключить
  сон в «Электропитании», на Linux — `systemd-inhibit ./run.sh`.

### Кнопки в панели не реагируют

- **Ни тоста, ни записи в журнале.** Чаще всего это старая страница в браузере:
  HTML с кнопкой успел обновиться, а `app.js` — нет, и нажатие молча ничего не
  делает. Нажмите `Ctrl+Shift+R` (или закройте вкладку и откройте
  `http://127.0.0.1:8765/` заново). Признак устаревшей страницы: чип «вступление…»
  так и не меняется на «вступление: <дата и время>».
- **Проверьте адрес страницы.** Открывать нужно `http://127.0.0.1:8765/`; ссылка
  `/panel/index.html` перенаправляется на `/`, потому что статикой эта страница
  отдавалась без CSRF-токена и все изменяющие запросы получали 403.
- **«Остановить панель» вернула «Недействительный CSRF-токен».** Страница осталась
  от прошлого запуска панели — обновите её (`Ctrl+Shift+R`) и нажмите снова.
  Панель при этом жива: остановка не заказана, кнопка снова активна.
- **Нажали «Остановить панель», а панель не выключается.** Оверлей со счётчиком
  секунд — это нормальное ожидание: если идёт прогон, панель дожидается его до
  15 секунд. Ждёт дольше минуты — смотрите журнал и `./stop.sh`; если панель уже
  запускали заново, закройте страницу и откройте её снова.
- **Загляните в журнал (вкладка «Журнал»).** Панель пишет `Панель: запуск (join,
  вручную) принят` либо `Панель: запуск (join) отклонён: Прогон уже выполняется`.
  Нет ни одной из этих строк — запрос не дошёл до панели (старая страница);
  есть «отклонён» — дождитесь конца текущего прогона: одновременно рассылка и
  вступление не запускаются, профили Firefox у них общие.
- **Чип «код новее — перезапустите панель»** означает, что после запуска панели
  правился `*.py` / `panel/*`: перезапустите панель (`Ctrl+C` в её окне или
  `./stop.sh`, если окна нет, затем `./web.sh`), иначе работает старый код —
  например, вступление не будет помечать группы в `closed_groups.txt`.

## Безопасность

Каталог `profiles/` (а также `logs/`) исключён из git. Не публикуйте содержимое
профилей: оно даёт полный доступ к аккаунту WhatsApp. Удаление профиля
необратимо — сессия WhatsApp и `bot_stats.json` пропадают вместе с каталогом.
